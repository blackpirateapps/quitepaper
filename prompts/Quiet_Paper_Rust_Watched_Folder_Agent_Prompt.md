## 4. Architectural boundary and bridge contract

**Rust owns**: native watcher, recursive discovery, file eligibility, file stability scheduling, directory reconciliation, safe file opening, byte streaming/hash, duplicate-candidate work scheduling, bounded backpressure, cancellation, retry timers, watch health state, and native error classification. Rust does **not** write a second copy of Quiet Paper's notes/tags/search/sync schema. It does not parse EML again.

**Dart owns**: UI and settings Riverpod state; a narrow `WatchedImportRepositoryAdapter` (Drift migration, durable jobs, dedup receipts, folder enrollment decision, atomic note+receipt commit); a `CanonicalImportAdapter` that invokes the **existing** EML/PDF/Markdown/text/image import pipeline in headless mode with no Navigator; and the existing encrypted attachment/vault/index/sync services. The app's existing import pipeline is the only code allowed to turn the accepted file into a note. Any existing UI-dependent importer should be separated into thin UI wrapper + shared headless application service without changing existing behavior.

### Rust↔Dart interface (typed, no stringly-typed event JSON)

Implement a versioned bridge contract equivalent to:

- `initialize_watched_import_engine(config, event_sink)` → engine handle and health status;
- `start_watch(handle, root_path, include_subfolders=true)`;
- `pause_watch(handle)` / `resume_watch(handle)` / `shutdown_watch(handle)`;
- `reconcile_now(handle)` and `set_vault_ready(handle, bool)`;
- `inspect_root(root_path)` (permissions, canonical root, supported candidates and totals for review);
- `submit_import_outcome(handle, job_id, result)` to release or retry native work;
- typed event stream: `Discovered`, `StableCandidate`, `RootUnavailable`, `WatchDegraded`, `ScanProgress`, `Paused`, `Error`, `Stopped`; every candidate has job ID, root ID, observed path, size, observed identity/mtime, content SHA, and an immutable generation token.

If a concrete FRB API has slightly different callback/event syntax, preserve this behavior. Use structured error codes and sanitized context; do not send entire email contents or attachment bytes as progress events. Ensure all callbacks are no-ops after shutdown, no dangling Dart callbacks, no event delivery into disposed UI, and idempotent start/stop. A native worker cannot start importing a candidate until Dart has durably enrolled/reviewed the folder and established that the vault is ready. No Rust-driven unbounded concurrent callbacks to Dart.

**Cross-language import protocol**: Rust detects, stabilizes and hashes a candidate. Dart checks the authoritative Drift receipt and durable job state; reserves the attempt; uses the current canonical importer with an expected source hash and source revision; stages attachments using existing encrypted storage; verifies the **actual bytes consumed by import** match the expected digest/size; and atomically commits the created note, tags, search/sync metadata, and success receipt in the authoritative DB. A mismatch rolls back/quarantines staging and requests a recheck. On restart, receipt lookup decides the result; a missing native acknowledgement never constitutes a second import. If the existing importer cannot accept an immutable opened source, add a narrowly scoped streaming/snapshot abstraction to that importer. Do **not** trust a stale path between Rust's hashing and Dart's open; enforce final content verification. Avoid plaintext on-disk snapshots. Prefer bounded streaming into the existing encrypted asset-staging mechanism, with a durable recovery journal for orphaned encrypted stages.
